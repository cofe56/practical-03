# Практична робота №3. Створення вебформ різного рівня складності

**Тема:** Створення форм реєстрації, входу та введення предметних даних із семантичною структурою, доступними підписами й вбудованою HTML-валідацією.  
**Проєкт:** «AeroHub» — інформаційний вебпортал про цивільну та військову авіацію, безпілотні системи та авіаційні технології.

## 2. Призначення форм, вибір HTTP-методів та майбутні маршрути

Для всіх трьох розроблених форм обрано метод надсилання **`POST`**.

| Форма | Файл | Метод | Майбутній маршрут (`action`) | Обґрунтування вибору методу |
| :--- | :--- | :---: | :--- | :--- |
| **Вхід до системи** | `login.html` | `POST` | `/login` | Передаються конфіденційні облікові дані (пароль). Метод `POST` передає дані в тілі HTTP-запиту, унеможливлюючи їх збереження в URL-адресі, історії браузера, кеші та серверних логах. Конфіденційність каналу забезпечуватиметься протоколом HTTPS. |
| **Реєстрація** | `register.html` | `POST` | `/register` | Створення нового облікового запису користувача з передачею нового пароля. Перевірка збігу полів пароля, хешування та безпечне збереження делегуються майбутньому бекенду. |
| **Створення матеріалу** | `news-form.html` | `POST` | `/articles/create` | Створення нового ресурсу з великим обсягом текстових даних (`textarea`), параметрами рубрики та станом публікації. Рядок запиту `GET` має обмеження на довжину і не призначений для операцій модифікації стану системи (mutation). |

## 3. Зведена таблиця правил HTML-валідації

Усі правила валідації визначені виключно на основі логіки предметної галузі «Авіаційний портал AeroHub».

| Поле форми | HTML-елемент та `type` | Обов'язкове (`required`) | Атрибути обмежень | Предметне обґрунтування |
| :--- | :--- | :---: | :--- | :--- |
| **Email** (`login.html`, `register.html`) | `<input type="email">` | Так | Вбудований синтаксис email | Ідентифікатор користувача; потрібен коректний синтаксис для листування та відновлення доступу. |
| **Поточний пароль** (`login.html`) | `<input type="password">` | Так | `required` | Автентифікація чинного облікового запису. Специфічні обмеження на клієнті відсутні, щоб не блокувати старі паролі користувачів. |
| **Ім'я або позивний** (`register.html`) | `<input type="text">` | Так | `minlength="2"`, `maxlength="80"` | Відображуване ім'я автора має бути змістовним (не менше 2 символів) і не повинно деформувати інтерфейс сайту. |
| **Новий пароль** (`register.html`) | `<input type="password">` | Так | `minlength="8"` | Базова вимога довжини пароля для початкового рівня захисту акаунту. |
| **Підтвердження пароля** (`register.html`) | `<input type="password">` | Так | `minlength="8"` | Поле для майбутнього звіряння збігу на стороні клієнта/сервера. |
| **Згода з правилами** (`register.html`) | `<input type="checkbox">` | Так | `required` | Юридична згода читача/автора з правилами ресурсу перед завершенням реєстрації. |
| **Заголовок матеріалу** (`news-form.html`) | `<input type="text">` | Так | `minlength="5"`, `maxlength="120"` | Заголовок новини має чітко розкривати суть події, уникаючи клікбейтного шуму або випадкових коротких введень. |
| **Тематичний розділ** (`news-form.html`) | `<select>` | Так | `required` (перша опція з `value=""`) | Кожна стаття обов'язково повинна належати до однієї з рубрик каталогу порталу. |
| **Тип публікації** (`news-form.html`) | `<input type="radio">` | Так | Група з однаковим `name="articleType"` | Взаємовиключний вибір формату матеріалу: новина, стаття або технічний огляд. |
| **Дата події** (`news-form.html`) | `<input type="date">` | Так | Вбудований календар | Фіксація точної календарної дати польоту, авіашоу або релізу. |
| **Орієнтовний час читання** (`news-form.html`) | `<input type="number">` | Так | `min="1"`, `max="60"`, `step="1"` | Вказує час ознайомлення в хвилинах. Відсікає від'ємні значення та нереалістичні показники. |
| **Повний зміст** (`news-form.html`) | `<textarea>` | Так | `minlength="30"`, `maxlength="5000"` | Повноцінне тіло статті. Запобігає публікації пустих чернеток та переповненню сховища. |
| **Параметри публікації** (`news-form.html`) | `<input type="checkbox">` | Ні | Опційні прапорці | Незалежні перемикачі для терміновості новини та дозволу коментарів. |

## 4. Семантика, доступність (Accessibility) та автозаповнення

1. **Зв'язок підписів і полів:**  
   Кожне поле введення має відповідний текстовий елемент `<label>`. Зв'язок реалізовано явно через комбінацію атрибутів `for="<id>"` та унікального `id` на елементі введення. Атрибут `placeholder` не використовується як замінник назви поля.

2. **Підказки та інструкції:**  
   Поля, що мають обмеження формату (наприклад, довжина пароля чи правила складання заголовка), забезпечені видимими інструкціями у вигляді тегів `<p id="...">` та програмно пов'язані з елементами форми за допомогою атрибута `aria-describedby`.

3. **Групування controls:**  
   Взаємовиключні радіокнопки (тип матеріалу) та незалежні чекбокси (параметри публікації) згруповані за допомогою тегів `<fieldset>` зі спільним тематичним заголовком `<legend>`.

4. **Токени автозаповнення (`autocomplete`):**
   * `login.html`: використано `autocomplete="email"` та `autocomplete="current-password"`.
   * `register.html`: використано `autocomplete="name"`, `autocomplete="email"` та `autocomplete="new-password"`.  
   Це дозволяє менеджерам паролів і браузерам коректно пропонувати збережені дані та зберігати нові паролі без конфліктів.

5. **Клавіатурна доступність:**
   * Усі елементи форми доступні для послідовного переходу за допомогою клавіші `Tab`. Порядок фокусування відповідає логічній розмітці в DOM-дереві (штучні позитивні `tabindex` не застосовувалися).
   * Радіокнопки перемикаються клавішами зі стрілками, прапорці активуються клавішею `Space`, а відправка форми викликається натисканням `Enter` у текстових полях або активацією кнопки `Submit`.

## 5. Перевірка результатів

1. **Збір даних через `FormData`:**  
   Усі елементи введення мають атрибут `name`, що відповідає структурі моделі даних. Працездатність перевірено у консолі браузера (DevTools Console):
   ```javascript
   const form = document.querySelector("form");
   console.table([...new FormData(form).entries()]);
   ```
   Усі поля генерують очікувані пари `name=value`.

2. **Валідація розмітки:**  
   Усі створені документи (`index.html`, `login.html`, `register.html`, `news-form.html`) успішно пройшли перевірку валідатором **Nu HTML Checker** без критичних помилок (Errors).
